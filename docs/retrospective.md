# POS Manager 개발 회고

코딩 경험이 없던 현장 직원이 Gemini와 메시지 245개를 주고받으며 이 앱을 만들었다. 이 문서는 그 대화 원문을 AI(Claude)와 함께 처음부터 끝까지 다시 읽고 정리한 회고다. 아래 `#번호`는 대화에서 몇 번째 메시지인지를 뜻한다(#0이 첫 메시지).

- **기간:** 대화방을 한 달 이상 사용(#166). 최종 파일 날짜는 2026년 4월 4일~12일.
- **도구:** 처음에는 Node.js로 안내받았다가 파이썬(Flask)으로 바꿨고(#1), 메모장과 cmd만으로 개발했다(#108). UI 시험용 Streamlit 버전("26.0")을 따로 만들었다가 본 프로젝트와 합쳤다(#188).
- **결과:** 가맹점 등록·검색, 장비 변경 이력, 예정/완료 업무 관리는 동작한다. 티맵 다중 경유지 길찾기는 끝내 동작하지 않았고, 프로젝트는 #242에서 멈췄다.

## 티맵 연동이 실패한 진짜 원인

화면에 뜨던 "주소가 명확하지 않습니다"는 실제 원인과 상관없이 코드에 고정된 문구였다. 어떤 오류가 나도 같은 문구가 떴고, AI는 자기가 쓴 그 문구를 믿고 주소 처리만 계속 고쳤다.

1. **공식 지원되지 않는 호출 방식:** 티맵 앱을 열 때 경유지 파라미터를 넣었지만, 공개된 티맵 앱 호출 방식에서는 목적지 1곳만 확인된다. "폰에서 들어가도 그냥 티맵만 실행되고 끝"(#227)이었던 이유다.
2. **지도가 만들어지지 않았다:** 지도를 만드는 코드를 다른 시작 코드가 덮어썼다.
3. **오류를 전부 같은 문구로 덮었다:** 진짜 오류 내용은 어디에도 남지 않았다.
4. **좌표를 한 칸만 읽었다:** 도로명 좌표만 읽고 지번 좌표는 읽지 않았다.
5. **추가 주소가 있는 가맹점은 '경로추가' 버튼이 깨져 있었다.**

당시 내 직감은 맞는 방향이었다. #233에서 "좌표값 양식이 다른 거 아니야?", #236에서 "주소가 저장될 때 좌표가 아니라 텍스트만 저장되는 거야?"라고 물었고, #238에서는 오류 문구가 남 탓이고 코드 문제라고 짚었다.

## 바이브 코딩에서 배운 점

- **파일 통째 교체는 기능을 잃는다.** 매번 전체 코드를 받아 붙여 넣으니 고친 부분 외에 잘 되던 기능이 자꾸 사라졌다(#202, #209, #212). 버전 관리(Git)가 있었다면 바로 되돌릴 수 있었다.
- **대화가 길어지면 AI는 앞부분을 잊는다.** 요구사항 요약을 부탁하자 최근 내용만 나오거나 없는 내용을 지어냈다(#158–#166). 요구사항은 대화가 아닌 별도 문서에 쌓아야 한다.
- **오류를 숨기면 아무도 고칠 수 없다.** 브라우저 개발자 도구(F12) 콘솔에 진짜 오류가 찍히게 했다면 한 번에 찾을 수 있었다.
- **"완벽합니다"는 검증이 아니다.** AI가 자기 코드를 실행해 보지 않고 고쳤다고 말했다. #230에서 "테스트를 먼저 하고 보내면 안 돼?"라고 한 요구가 정확한 해법이었다.
- **공식 문서가 먼저다.** 티맵 경유지 호출은 애초에 공식 지원이 확인되지 않는 방식이었다. 안 되는 방법을 수백 번 고치기 전에, 되는 방법이 있는지부터 확인해야 했다.
- **기능을 빼는 판단도 기획이다.** #95에서 스캔 기능을 뺀 것처럼, 직원들이 실제로 쓸지를 먼저 물었다.
